# R1 · 演示脚本：「一个工单的一生」（T41）

> 演示前准备：
> 1. 启动后端（`cd CPS/backend && mvn spring-boot:run`），确认控制台出现「[Seed] 种子数据初始化完成」（首次）；
> 2. 打开管理端（`cd CPS/admin-web && npm run dev` → http://localhost:5173）；
> 3. 微信开发者工具导入 `CPS/miniprogram`，详情设置勾选「不校验合法域名」；
> 4. 建议窗口布局：管理员浏览器 + 学生模拟器 + 维修工模拟器。

**账号**：admin1（管理员）/ student01（学生）/ worker01（维修工·水电+空调·大学城校区）/ worker02（维修工·水电·大学城校区）/ worker03（维修工·网络+实验·龙洞校区），密码均为 123456

## 主线演示（约 5 分钟）

### ① 学生提交
student01 登录小程序 → 「我要报修」→ 校区选「大学城校区」，详细位置填「1号宿舍楼 101」→
类型「空调家电」→ 描述"宿舍空调不制冷，出风只有常温" → 拍 1–2 张照片 → 提交。
**展示点**：工单号 BX+日期+序号；提示跳转「我的报修」。

### ② 学生跟踪
「我的报修」→ 状态「待审核」→ 点进详情看时间线「我提交了报修」。

### ③ 管理员审核
admin1 登录管理端 → 「审核工作台」→ 看到 URGENT 单置顶红显 → 详情抽屉查看图片 → 「通过」。

### ④ 管理员派单
「派单工作台」→ 选中该单 → 右侧看板：**指给评委看**——赵敏（负责龙洞校区）因「负责校区不含工单校区」置灰并显示原因；
大学城校区维修工（张强/李国栋/孙志刚/周建国）可选 → 「派单给 张强」。
**展示点**：硬约束过滤（技能/校区/在岗/负载）的可解释性。

### ⑤ 维修工接单
张强小程序「维修工单」→ 待接列表出现新单 → 详情看描述与图片 → 「📞 点击拨打」学生电话 → 「接单」。

### ⑥ 完工上报
张强「在办」→ 该单 → 「完工上报」→ 拍 1 张完工照 + 说明"更换启动电容，制冷恢复" → 确认完工。

### ⑦ 学生评价
student01「我的报修」→ 该单状态已变「已完成」→ 「去评价」→ 5 星 + "速度很快" → 提交。
**展示点**：状态变「已评价」，时间线六步完整（提交→审核通过→派单→接单→完工→评价）；
管理端「工单管理」抽屉同款时间线，维修工评分已更新。

## 异常分支补演（约 2 分钟）

### ⑧ 驳回重报
student02 提交一张普通单 → admin1 审核时选「驳回」，理由"照片无法看清故障位置" →
student02 详情页出现驳回理由提示 → 「补充重报」补充描述与图片 → 状态回「待审核」。

### ⑨ 拒单回池
admin1 将另一张教学区单派给李国栋 → 李国栋「拒单」（理由"时间冲突"）→
工单回到待处理池，管理端可重新派单。

### ⑩ 并发接单（可选，答辩加分）
管理端派单给某师傅后，用脚本 `node scripts/concurrent-accept.mjs` 演示 5 次并发接单仅 1 次成功——乐观锁幂等。
